# Internationalization (i18n)

The framework uses **vue-i18n** with a namespace-based file structure supporting English and Arabic out of the box.

## File Structure

```
src/i18n/
├── index.ts              # i18n instance setup
└── locales/
    ├── en/
    │   ├── common.json   # Shared labels (Save, Cancel, etc.)
    │   ├── users.json    # Users resource translations
    │   ├── menu.json     # Navigation labels
    │   └── validation.json
    └── ar/
        ├── common.json
        ├── users.json
        ├── menu.json
        └── validation.json
```

Each JSON file becomes a **namespace**. The file name is used as the top-level key:

```json
// src/i18n/locales/en/users.json
{
  "fields": {
    "name": "Name",
    "email": "Email"
  },
  "status": {
    "active": "Active",
    "inactive": "Inactive"
  }
}
```

Access keys as `namespace.path`:

```ts
t('users.fields.name')     // → "Name"
t('common.save')           // → "Save"
t('menu.home')             // → "Home"
```

## Using in Components

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'

const { t } = useI18n()
</script>

<template>
  <h1>{{ t('users.fields.name') }}</h1>
</template>
```

## Using in Resource Configs

Wrap your config in a function to access `useI18n()`:

```ts
import { useI18n } from 'vue-i18n'

export function usersConfig(): ResourceConfig {
  const { t } = useI18n()

  return {
    columns: [
      { key: 'name', label: t('users.fields.name', 'Name') },
    ],
    // ...
  }
}
```

::: tip
Always provide a fallback string: `t('key', 'Fallback')`. This ensures the UI is readable even if a translation is missing.
:::

## Adding a New Locale File

1. Create the JSON file in both locale directories:
   ```
   src/i18n/locales/en/products.json
   src/i18n/locales/ar/products.json
   ```

2. The file is auto-detected by Vite's `import.meta.glob` — no manual registration needed.

3. Use it immediately:
   ```ts
   t('products.fields.price')
   ```

## URL Locale Structure

All routes support locale prefixing:

```
/en/admin/users       → English
/ar/admin/users       → Arabic
```

The router extracts the `/:lang` parameter and sets the locale automatically. RTL direction is set for Arabic:

```ts
document.documentElement.dir = locale === 'ar' ? 'rtl' : 'ltr'
document.documentElement.lang = locale
```

## Changing Locale Programmatically

```ts
import { setLocale } from '@/i18n'

setLocale('ar')  // Switches to Arabic, sets RTL, persists to localStorage
```

## Checking Missing Keys

### Generate a Report

```bash
bun i18n:report
```

This runs two steps:
1. **`i18n:prep`** — Merges all namespace files per locale into `.i18n-temp/en.json` and `.i18n-temp/ar.json`
2. **`vue-i18n-extract`** — Scans all `.vue`, `.ts`, and `.js` files for `t()` calls and compares against the merged locale files

The report is saved to `i18n-report.json` with all missing and unused keys.

### CI Check

```bash
bun i18n:check
```

Same as `i18n:report` but runs in CI mode — **exits with error code** if there are missing keys. Add this to your CI pipeline.

### How i18n:prep Works

The `scripts/i18n-prep.ts` script:
1. Reads all JSON files from `src/i18n/locales/en/` and `src/i18n/locales/ar/`
2. Merges them into single flat files: `.i18n-temp/en.json` and `.i18n-temp/ar.json`
3. These merged files are what `vue-i18n-extract` uses to find missing keys

::: warning
The `.i18n-temp/` directory is auto-generated. Don't edit or commit it.
:::

## Supported Locales

```ts
export const SUPPORTED_LOCALES = ['en', 'ar']
export const DEFAULT_LOCALE = 'en'
```

To add a new locale (e.g., French):
1. Add `'fr'` to `SUPPORTED_LOCALES`
2. Create `src/i18n/locales/fr/` with all namespace files
3. Add `const localesFr = import.meta.glob(...)` in `src/i18n/index.ts`
4. Call `buildMessages(localesFr, 'fr')`
